**UC-5**. Перенести меню
**Основной актор.** Пользователь
**Дополнительные акторы.** AI-агент, База данных RAG продуктов и цен 
**Описание.** Пользователь сдвигает все меню на выбранное количество дней N вперед (от 1 до 6 дней). Блюда каскадным сдвигом перемещаются в пределах текущего промежутка генерации; если последнее блюдо не помещается в границы текущего промежутка генерации, они удаляются из плана. Количество N дней, с которых был совершен сдвиг, остается пустым. Система пересчитывает список покупок и контролирует соблюдение недельных ограничений бюджета и КБЖУ.
**Триггер**. Пользователь нажимает кнопку «Перенести меню» в текущем меню.

**Предварительные условия:**
	PRE-1. Пользователь авторизован.
	PRE-2. Профиль пользователя настроен, указаны ограничения: бюджет, КБЖУ, аллергены, предпочтения.
	PRE-3. У пользователя есть активное сгенерированное меню на выбранный промежуток генерации.

**Выходные условия:**
	POST-1. Все блюда меню сдвинуты на N дней вперед в пределах текущего промежутка генерации.
	POST-2. Блюдо, не поместившееся в границы выбранного промежутка генерации, удалены из плана. 
	POST-3. Список покупок автоматически обновился.
	POST-4. Лимиты (бюджет и КБЖУ) остаются в рамках допустимых значений. 
	POST-5. Первые N дней недели остались пустыми, не имея меню.

**Нормальное направление развития варианта использования:**
5.0 Инициировать сдвиг меню
	1. Пользователь нажимает кнопку «Перенести меню».
	2. Система отображает диалог выбора количества дней сдвига (от 1 до 6) с сообщением: «На сколько дней сдвинуть меню?».
	3. Пользователь выбирает N дней.
	4. Система отображает превью сдвига: список всех блюд с указанием, куда они переместятся.
	5. Система отображает сообщение-предупреждение: «Блюда, не поместившиеся в границы {выбранный промежуток}, будут удалены».
	6. Система запрашивает у пользователя подтверждение: Блюда последних {N} дней ({список названий}) будут удалены из плана. Продолжить?».
	7. Пользователь нажимает кнопку «Да», подтверждая сдвиг.
	8. Система выполняет каскадный сдвиг всех блюд на N дней вперед в пределах выбранного пользователем промежутка генерации. 
	9. Система удаляет не поместившиеся в границы блюда из плана.
	10. Система оставляет первые N дней пустыми. 
	11. Система пересчитывает список покупок и прогнозирует итоговые КБЖУ и бюджет на промежуток для генерации.
	12. Система показывает уведомление: «Меню сдвинуто на {N} дней. Удалено блюд: {количество}».  

**Альтернативное направление развития варианта использования:**
5.1 Пользователь передумал после превью
	1. Когда система предупреждает об удалении блюд, пользователь нажимает кнопку «Нет», отменяя сдвиг.
	2. Система завершает вариант использования.

5.2 Сегодня последний день промежутка генерации меню
	1. Пользователь нажимает кнопку «Перенести меню».
	2. Система отображает сообщение: «Сегодня последний день текущего меню. Сдвиг за пределы невозможен. Используйте "Заменить блюдо" для отдельных приемов пищи».
	3. Система завершает вариант использования.

5.3 Пользователь выбирает максимальный сдвиг (6 дней)
	1. Система отображает диалог выбора количества дней сдвига (от 1 до 6) с сообщением: «На сколько дней сдвинуть меню?».
	2. Пользователь выбирает 6 дней.
	3. Система отображает особое предупреждение: «При сдвиге на 6 дней будет удалено 6 из 7 дней меню. Продолжить?».
	4. Система продолжает нормальное направление варианта использования.

**Исключения:**
5.0.E1 Сдвиг нарушает недельные ограничения
	1. При пересчете списка покупок и прогнозировании итоговых КБЖУ и бюджета на неделю система обнаруживает, что бюджет превышен >20% или КБЖУ вышло за коридор ±10%.
	2. Система отображает сообщение-предупреждение: «Сдвиг нарушит недельный бюджет/КБЖУ. Продолжить?».
	2a. Пользователь нажимает кнопку «Да».
	3a. Система применяет замену с пометкой нарушения ограничения. 
	4а. Система завершает вариант использования.
	2б. Пользователь нажимает кнопку «Нет».
	3б. Пользователь отменяет сгенерированную замену с нарушением ограничений.
	4б. Система предлагает пользователю скорректировать бюджет или КБЖУ. 
	5б. Система заново начинает нормальное направление варианта использования.

5.2.E1 Блюда последнего дня приготовлены
	1. Пользователь нажимает кнопку «Перенести меню».
	2. Система обнаруживает, что в меню на последний день осталось менее 2 активных блюд.
	3. Система отображает сообщение: «В меню недостаточно блюд для сдвига. Сгенерируйте новое меню на неделю».
	4. Система завершает вариант использования.

**Приоритет**: Высокий
**Частота использования**: 1-2 раза в неделю
**Бизнес-правила**: ACTION-05, CONSTRAINT-01, CONSTRAINT-02, CONSTRAINT-03, CONSTRAINT-05, CONSTRAINT-15, CONSTRAINT-16, COMPUTATION-02, COMPUTATION-03, FACT-04
**Специальные требования**: Время пересчета меню ≤ 2 секунды
**Предположения**: Пользователь понимает, что сдвиг меню на N дней означает удаление последних N дней меню. Пустые дни пользователь заполнит через другие UC в течение недели.

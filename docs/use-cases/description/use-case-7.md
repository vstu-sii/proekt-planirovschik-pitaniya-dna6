**UC-7**. Сгенерировать быстрый ужин
**Основной актор.** Пользователь
**Дополнительные акторы.** AI-агент, Локальная база данных продуктов пользователя «Мои продукты»
**Описание.** Пользователь нажимает кнопку «Быстрый ужин», и система генерирует 3 варианта ужина со временем приготовления ≤ 30 минут и минимальным количеством шагов. Система использует продукты из локальной базы «Мои продукты» с приоритетом скоропортящимся продуктам, а при ее отсутствии используется набор базовых продуктов (яйца, крупы, масло, специи). Все варианты учитывают диетические ограничения и аллергены из профиля пользователя.
**Триггер**. Пользователь нажимает кнопку «Быстрый ужин» на главном экране.

**Предварительные условия:**
	PRE-1. Пользователь авторизован.
	PRE-2. Профиль пользователя настроен, указаны ограничения: бюджет, КБЖУ, аллергены, предпочтения.

**Выходные условия:**
	POST-1. Пользователь получил 1-3 варианта рецептов с временем приготовления ≤ 30 минут и минимальным количеством шагов.
	POST-2. Если в рецепте были дополнительные ингредиенты, не входившие в «Мои продукты», они добавляются в список покупок.

**Нормальное направление развития варианта использования:**
7.0 Инициировать быстрый ужин
	1. Пользователь нажимает кнопку «Быстрый ужин» на главном экране.
	2. Система автоматически подтягивает список продуктов из локальной базы «Мои продукты», отсортированный по сроку годности.
	3. Если база «Мои продукты» пуста, система использует виртуальный список «базовых продуктов» (яйца, крупы, замороженные овощи, масло, специи).
	4. Система формирует запрос к AI-агенту с условиями: обязательное использование имеющихся/базовых продуктов; время готовки ≤ 30 минут; минимальное количество шагов приготовления; соблюдение аллергенов и диет из профиля.
	5. AI-агент возвращает 3 варианта рецептов с кратким описанием, временем готовки, списком ингредиентов и расчетом КБЖУ.
	6. Система отображает 3 варианта рецептов пользователю. 
	7. Пользователь выбирает один из 3 вариантов и нажимает «Начать готовку».
	8. Пользователь выбирает один рецепт и нажимает «Подтвердить».
	9. Система отображает сообщение: «Рецепт сохранен».

**Альтернативное направление развития варианта использования:**
7.1 Пользователь пропускает этап отметки имеющихся продуктов
	1. Пользователь нажимает «Пропустить» на этапе отметки галочками оставшихся продуктов.
	2. Система не учитывает оставшиеся продукты в запросе к AI-агенту.
	3. AI-агент генерирует рецепты из базовых продуктов.
	4. Система продолжает нормальное направление варианта использования.

7.2 Пользователь недоволен предложенными рецептами
	1. Пользователь нажимает «Предложить другие варианты».
	2. Система повторно запрашивает у AI-агента 3 новых рецепта с расширенным списком допустимых дополнительных ингредиентов.
	3. Система продолжает нормальное направление варианта использования.

**Исключения:**
7.0.E1 Добавление базовых ингредиентов
	1. AI-агент не может собрать полноценный рецепт только из указанных остатков.
	2. Система отображает сообщение: «Разрешите добавление базовых ингредиентов (например, яйца, макароны, мука, масло) для большего выбора рецептов».
	3а. Пользователь нажимает кнопку «Да».
	4а. Система продолжает нормальное направление варианта использования.
	3б. Пользователь нажимает кнопку «Нет».
	4б. Система отображает сообщение: «Невозможно сгенерировать блюдо из этих продуктов. Попробуйте добавить еще ингредиенты или выберите другие продукты из остатков» (см. 5.0.E2).
	5б. Система завершает вариант использования. 

7.0.E2 AI-агент не может сгенерировать рецепт из указанных продуктов
	1. AI-агент не находит подходящих рецептов. 
	2. Система отображает сообщение: «Невозможно сгенерировать блюдо из этих продуктов. Попробуйте добавить еще ингредиенты или выберите другие продукты из остатков». 
	3а. Пользователь добавляет ингредиенты
	4а. Система продолжает нормальное направление варианта использования.
	3б. Пользователь изменяет список остатков.  
	4б. Система продолжает нормальное направление варианта использования.
	3в. Пользователь отменяет операцию с помощью кнопки «Отмена».
	4в. Система завершает вариант использования.

7.0.E3 Недоступен AI-агент или RAG-база
	1. Система не получает ответ от AI-агента в течение превышенного времени, установленном SLO (~15 секунд).
	2. Система отображает сообщение: «Сервис временно недоступен. Попробуйте позже».
	3. Пользователь отменяет генерацию меню.
	4. Система завершает вариант использования.

7.0.E4. Указанные продукты содержат аллергены из профиля
	1. Пользователь вводит продукт, который входит в список его аллергенов.
	2. Система отображает предупреждение: «Вы указали продукт, на который у вас аллергия: {название}. Продолжить?»
	3а. Пользователь подтверждает осознанный выбор. 
	4а. Система продолжает нормальное направление варианта использования.
	3б. Пользователь удаляет продукт из списка.
	4б. Система продолжает нормальное направление варианта использования.

7.0.E5. Локальная база «Мои продукты» пуста
	1. Пользователь нажимает «Zero-Waste Рецепт».
	2. Система обнаруживает, что в локальной базе нет ни одного продукта.
	3. Система отображает сообщение: «У вас пока нет отмеченных запасов. Добавьте продукты вручную».
	4a. Пользователь выбирает «Добавить вручную».
	5а. Система продолжает нормальное направление варианта использования. 
	4б. Пользователь отменяет операцию с помощью кнопки «Отмена».
	5б. Система завершает вариант использования.

**Приоритет**: Средний
**Частота использования**: 2-4 раза в неделю на пользователя
**Бизнес-правила**: ACTION-02, FACT-04, CONSTRAINT-04, CONSTRAINT-10, CONSTRAINT-11, CONSTRAINT-15, CONSTRAINT-16, COMPUTATION-04, COMPUTATION-05, COMPUTATION-06
**Специальные требования**: SLO < 5 сек (95% запросов), SLA < 8 сек (99% запросов)
**Предположения**: Локальная база данных «Мои продукты» доступна. AI-агент имеет доступ к достаточно широкой базе рецептов, чтобы генерировать варианты из остатков. Пользователь честно указывает имеющиеся продукты.

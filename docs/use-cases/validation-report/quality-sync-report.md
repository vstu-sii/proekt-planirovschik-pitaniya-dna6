# Сверка с Quality

**Прогон:** 2026-11-05.
**Назначение:** детализировать модельные находки Quality, которые не входят в 50-строчную сводку `bug-list.md`, и зафиксировать расхождения, `null`-метрики, safety-кейсы и вопросы Q-01 - Q-05.

## 1. Что изменилось после сверки

- Первичная сверка выполнялась на реестре из 63 находок; после ручной консолидации `bug-list.md` содержит **50 базовых находок** (`BUG-001…BUG-050`).
- Модельные находки Quality выделены отдельно: **8**   `BUG-E1…BUG-E8`. В таблицы `bug-list.md` и `02-breaks.md` они не дублируются, чтобы не смешивать модельные и продуктовые разрывы.
- Суммарно к планированию доступно **58 находок** (50 базовых + 8 модельных), но сводка `bug-list.md` намеренно считает только базовые 50.
- Ранее `BUG-E4` и `BUG-E7` считались DUP-алиасами к контрактным находкам старого реестра; в текущем реестре таких строк нет, поэтому обе находки ведутся как самостоятельные модельные.
- Новых продуктовых находок по итогам сверки не добавлено; расхождения с Quality вынесены в §5, вопросы   в §4.

Источники:

- **Базовый реестр:** `bug-list.md`   50 продуктовых/кодовых находок `BUG-001…BUG-050`; модельные `BUG-E1…BUG-E8` перечислены ссылкой, но в сводку 50 не входят.
- **Разрывы по UC:** `02-breaks.md`   50 базовых находок; модельные `BUG-E*` здесь не дублируются.
- **Продуктовые наблюдения:** `03-surprises.md`   S-01…S-10 и Q-01…Q-05.
- **Карта покрытия:** `01-summary.md`   UC-1…UC-3 покрыты частично, UC-4…UC-9 не реализованы.
- **Технические артефакты Quality:** `docs/quality/lab3-eval-report.md`, `docs/quality/summary-full-v1.json`, `docs/quality/baseline-full-v1.jsonl`.
- **Продуктовый отчет:** `docs/quality/eval-report-1.md`   интерпретация «где врем» по боли пользователя.

## 6. Ограничения анализа

- Источники Quality находятся в `docs/quality/`: `lab3-eval-report.md`, `summary-full-v1.json`, `baseline-full-v1.jsonl`. Путей `docs/use-cases/quality_files/` в проекте нет.
- В `baseline-full-v1.jsonl` нет поля с текстом запроса (`query`/`input`), поэтому «что спросили» для `GD-0.2-013` и `GD-0.2-021` реконструировано по `missing_literal_terms` и ответу; это не дословная формулировка кейса.
- `budget_accuracy`, `nutrition_accuracy`, `allergen_compliance`, `critical_violations_verified`   `null`; `retrieval_metrics`   `N/A`; эти поля означают «не проверено», а не «нарушений нет».
- `literal_contains_pass_count`   буквальная проверка, не семантическая; 0/13 не равно «все ответы неверны по смыслу».
- Latency измерена только по 13 полученным ответам; нельзя считать ее SLA для всех 44 запросов.
- В `summary-full-v1.json` нет отдельной разбивки safety-critical; она взята из `lab3-eval-report.md` и jsonl.
- Модельные `BUG-E1…BUG-E8` не входят в сводку 50 базовых находок `bug-list.md`

# Что изменилось после прототипа

## 1. Итоги спринта 3

Прототип подтвердил, что концепция работает: API отвечает, UI отображает профиль, список продуктов, сгенерированное меню и стоимость. Базовая цепочка «профиль → продукты → меню» физически существует, поэтому продукт не нужно переизобретать с нуля.

При этом валидация 9 UC показала системные блокеры. Полноценно не работает ни один UC: 3 работают частично (UC-1, UC-2, UC-3), 6 не реализованы (UC-4 - UC-9); UC-8 и UC-9 исключены из MVP. В реестре 50 находок: 17 - P0, 22 - P1, 11 - P2.

Главный провал - базовый UC-3 «сгенерировать меню под мои продукты». Вместо AI-агента работает заглушка (BUG-021), меню не сохраняется и исчезает при перезагрузке (BUG-025), safety-ограничения не проверяются (BUG-022), показывается только первый день (BUG-023), а пустой список продуктов приводит в тупик (BUG-020). Модельный прогон добавляет структурный отказ контракта `MealPlanDraft` (BUG-E1) и неподтвержденную safety (BUG-E3). Пока это не исправлено, наращивать фичи нельзя: пользователь не получает персональное меню, которому можно доверять.

## 2. Обновление требований (v2)

Все явные правки требований зафиксированы в `05-changes.md`: 46 правок по UC-1, UC-2, UC-3 и архитектуре (CH-01 - CH-46). Каждая правка привязана к конкретному BUG-ID из `bug-list.md` или явно помечена как документационная.

Ключевые архитектурные изменения: отказ от RAG (работаем на фиксированной локальной БД «Мои продукты»), удаление UC-8 (расчет КБЖУ по фото, CV) и UC-9 (раздел «Коллекции») из скоупа MVP. Эти решения меняют не только объем, но и критерии приемки: из MVP уходят CV-пайплайн, векторный поиск и коллекции.

PRD обновлен до версии v2. Правки синхронизированы с `bug-list.md`, `01-summary.md`, [eval-report-1.md](quality/eval-report-1.md) и [quality-sync-report.md](use-cases/validation-report/quality-sync-report.md).

## 3. План спринта 4

Главная задача спринта: восстановить ядро UC-1, UC-2, UC-3. UC-4 - UC-7 остаются в MVP-бэклоге и планируются после стабилизации ядра; UC-8 и UC-9 вырезаны.

##### Блок А: Блокеры (P0): без них продукт не работает.

**UC-1**. Профиль:
- BUG-001. Нет авторизации. Боль: профиль не привязан к пользователю, персонализация и история недостоверны.
- BUG-006. Нет сохранения профиля. Боль: введенные рост, вес и бюджет теряются, сценарий обрывается.

**UC-2**. «Мои продукты»:
- BUG-010. Фиксированный список из трех позиций. Боль: нельзя вести свою продуктовую базу.
- BUG-011. Нет кнопки и формы «Добавить продукт». Боль: пользователь не может добавить то, что реально лежит дома.
- BUG-012. Нет поиска и подсказок. Боль: добавление продукта невозможно без ручного ввода КБЖУ.

**UC-3**. Генерация меню:
- BUG-018. Нет выбора длительности 7/3/1. Боль: нельзя спланировать ни день, ни неделю.
- BUG-020. Тупик при пустом списке продуктов. Боль: ошибка «Failed to fetch» и неработающая кнопка повтора блокируют сценарий.
- BUG-021. Заглушка вместо AI. Боль: меню не меняется под продукты, персонализация фиктивна.
- BUG-022. Не проверяются диеты и аллергены. Боль: риск для здоровья, safety-ценность не доказана.
- BUG-023. Показывается только первый день. Боль: недельный план фактически отсутствует.
- BUG-025. Нет сохранения в БД. Боль: перезагрузка страницы стирает меню и профиль.
- Модельные P0: BUG-E1 (структурный контракт `MealPlanDraft`) и BUG-E3 (safety-critical без ответа). Боль: без пригодного и безопасного ответа модели остальные метрики проверять нечего.

Вторая волна P0 (**UC-4, UC-5**): после закрытия ядра:
- BUG-027, BUG-028, BUG-029. Замена блюда: нет действия, альтернатив и применения замены.
- BUG-032, BUG-033, BUG-034. Перенос меню: нет кнопки, выбора N дней и каскадного сдвига.

##### Блок Б: Основной функционал (P1).

**UC-1**:
- BUG-002. Валидация бюджета 1000–100 000 ₽. Боль: некорректный бюджет проходит в генерацию.
- BUG-003. Пол, возраст, активность. Боль: расчет КБЖУ не учитывает профиль.
- BUG-004. Авторасчет и показ целевого КБЖУ. Боль: пользователь не видит цель, по которой строится меню.
- BUG-005. Справочник аллергенов. Боль: доступны только два ограничения, реальные аллергии не покрыты.
- BUG-007. Ручной ввод КБЖУ. Боль: нет обходного пути, если авторасчет не подходит.
- BUG-008. Загрузка сохраненного профиля. Боль: пользователь каждый раз начинает с констант.
- BUG-009. Сценарий ошибки сохранения. Боль: при сетевом сбое нет понятной обратной связи.

**UC-2**:
- BUG-013. Срок годности и единица измерения. Боль: нельзя отследить, что портится.
- BUG-014. Редактирование количества. Боль: остатки не соответствуют реальности.
- BUG-015. Перенос товаров из «Списка покупок». Боль: купленное не попадает в «Мои продукты».

**UC-3**:
- BUG-019. Ограничения из профиля не загружаются. Боль: меню строится без учета сохраненных ограничений.
- BUG-024. Нет фактических дневных КБЖУ. Боль: нельзя проверить, попадает ли день в цель.
- BUG-026. Список покупок не отображается. Боль: пользователь не может закупиться по плану.
- Модельные P1: BUG-E4, BUG-E5, BUG-E6, BUG-E7, BUG-E8   контракт КБЖУ/стоимости, семантика, метрики, latency и `meal_type`. Боль: без них нельзя доказать качество меню и соблюдение SLA.

**UC-4/UC-5** P1 (после P0-волны): BUG-030, BUG-031, BUG-035.

# ADR-004: Модульный монолит для серверной части

- Статус: принято
- Дата: 2026-10-28
- Участники решения: Product, AI Engineer, Delivery Engineer, Quality & Safety

## Контекст

Проект должен быстро дать работающий мобильный прототип, сохранять планы в PostgreSQL и
обращаться к LLM. Команда состоит из четырёх человек, а первая версия разворачивается одним
контуром. При этом бизнес-логика, AI-конвейер и точные расчёты должны иметь понятные границы.

## Решение

Использовать модульный монолит на FastAPI. Мобильное приложение обращается только к HTTP API.
Backend содержит отдельные модули профиля, каталога, планов питания, расчётов и AI-оркестрации,
но собирается и разворачивается как один сервис. Все постоянные данные хранятся в одной
PostgreSQL, доступной только backend.

LLM создаёт структурированную заготовку меню. Backend валидирует её, а стоимость и КБЖУ
рассчитывает обычным Python-кодом. В production backend обращается к GigaChat; локально его
заменяет `llm-mock` из Compose.

## Причины

- один сервис проще поднять, проверить и развернуть небольшой команде;
- транзакции и миграции остаются простыми;
- отсутствуют преждевременные сетевые границы между ещё нестабильными модулями;
- модульные границы позволяют позже выделить AI-конвейер или каталог в отдельный сервис.

## Последствия

Положительные:

- всё серверное приложение запускается и тестируется одним образом;
- секрет LLM и доступ к БД не попадают в мобильный клиент;
- отказ внешней модели можно обработать в одном месте;
- локальное окружение воспроизводимо через Docker Compose.

Ограничения:

- backend масштабируется целиком, а не по отдельным модулям;
- границы модулей нужно контролировать ревью и архитектурными проверками;
- единая БД усиливает связанность схемы, поэтому изменения выполняются миграциями.

## Отвергнутые варианты

### Микросервисы

Отвергнуты для MVP: добавляют сетевые отказы, несколько деплоев и распределённые транзакции,
но пока не дают команде измеримой пользы.

### Прямой вызов LLM из мобильного приложения

Отвергнут: раскрывает API-ключ, обходит серверную валидацию и мешает централизованно считать
стоимость, КБЖУ и качество результата.

### Локальная SQLite как основное хранилище

Отвергнута: приложение работает через интернет, планы должны быть доступны после смены
устройства, а AI-запросы всё равно выполняются сервером.

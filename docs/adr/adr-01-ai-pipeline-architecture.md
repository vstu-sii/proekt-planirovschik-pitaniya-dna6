# ADR-01: Архитектура AI-пайплайна

## Статус

## Контекст (Context)
Проект требует генерации персонализированного меню с точным расчетом стоимости и КБЖУ в пределах 30 секунд. LLM склонны к галлюцинациям при работе с точными числами и строгими ограничениями.

## Решение (Decision)
Использовать паттерн **Direct Prompt + Structured JSON + Python tools**. 

LLM отвечает только за:
- Смысловую генерацию (подбор блюд, комбинирование ингредиентов)
- Формирование структурированного черновика

Python tools отвечают за:
- Точный расчет стоимости (`calculate_cost()`)
- Точный расчет КБЖУ (`calculate_nutrition()`)
- Агрегирование ингредиентов (`aggregate_ingredients()`)
- Формальную проверку ограничений (`validate_constraints()`)

RAG и полноценный автономный агент в MVP не используются.
## Последствия (Consequences)
#### Плюсы (+)
- Гарантия точности числовых данных (нет галлюцинаций в расчетах)
- Высокая скорость генерации (подтверждено в Lab 1: ~3.88 сек)
- Простота отладки каждого компонента отдельно

#### Минусы (-)
- LLM не имеет прямого доступа к актуальным ценам без вызова инструментов
- Требуется строгая валидация JSON-схемы (в Lab 1 schema validity составила 88.9%, что требует реализации retry-логики)
- Нет возможности уточнять запрос у пользователя (нет диалога)

## Цена решения (Decision Cost)
Необходимость разработки и поддержки отдельного слоя Python-инструментов и валидаторов. Усложнение обработки ошибок (требуется логика Corrective prompt).

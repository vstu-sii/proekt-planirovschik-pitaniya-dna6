# Лабораторная № 3 — Quality & Safety: результаты первого baseline eval

## 1. Основание

Реальный пользовательский прогон `baseline-full-v1.jsonl` и `summary-full-v1.json`; 44 кейса Golden Dataset v1. Отчёт AI Engineer с показателем 43/44 относится к **другому прогону** и не подменяет эти результаты.

## 2. Подтверждённые показатели

| Метрика | Результат |
|---|---:|
| Всего кейсов | 44 |
| Получено ответов | 13/44 (29,55%) |
| Ошибок | 31/44 (70,45%) |
| Структурно валидные среди всех | 13/44 (29,55%) |
| Структурно валидные среди полученных | 13/13 (100%) |
| Средняя задержка полученных ответов | 3,2641 с |
| p95 задержки полученных ответов | 15,2794 с |
| Safety-critical кейсы | 16 |
| Safety-critical с ответом | 2/16 |
| Safety-critical с ошибкой | 14/16 |
| Буквальная проверка `must_contain` (полное совпадение) | 0/13 |

Из 31 ошибки 30 содержат сообщения `validation error` модели `MealPlanDraft`; ещё 1 относится к другой ошибке разбора/ответа. Основные признаки: пустые `days`, `meals`, `ingredients` при требованиях непустых списков. Список ID и точные ошибки — в `baseline-full-v1.jsonl`.

**Важно:** GD-0.2-007 в этом прогоне получил структурно валидный ответ, хотя в прежнем отчёте AI Engineer упоминался как невалидный. Это разные запуски; их результаты нельзя смешивать.

## 3. Метрики из карты качества

- Наличие ответа и структурная валидность: измерены, общий порог 95% не достигнут.
- Бюджет, КБЖУ, полнота меню, список покупок, остатки, тон: **не измерены семантическими валидаторами**.
- Соблюдение аллергенов и жёстких ограничений, число критических нарушений: **не подтверждены**; требуется ручная разметка и/или специализированные проверки. Отсутствие обнаруженных буквальных совпадений не равно безопасности.
- Retrieval/context: не измерялось, так как eval runner не интегрирован с ретривером; необходимо подтвердить отсутствие retrieval в целевом пайплайне.
- Задержки приведены **только для 13 полученных ответов**; нельзя считать их SLA для всех запросов.

## 4. Приоритетные действия

1. **P0:** исправить контракт/валидацию `MealPlanDraft` и повторить полный прогон; 31/44 кейсов не имеют ответа.
2. **P0:** вручную проверить 2 полученных safety-critical ответа (`GD-0.2-013`, `GD-0.2-021`) и повторить 14 неуспешных safety-кейсов.
3. **P1:** добавить семантические проверки бюджета, калорий, состава блюд, аллергенов и полноты сценариев.
4. **P1:** после исправления генератора провести регрессионный прогон по тому же v1 и отдельно по новым кейсам v2.
5. **P1:** передать Product VO этот отчёт и сырые ответы для документа «Где врём».

## 5. CI и воспроизводимость

Из корня объединённого проекта:

```powershell
python -m pytest -q backend/tests/evals/test_eval_runner.py backend/tests/evals/test_analysis.py
python -m backend.tests.evals.analyze_results --dataset docs/quality/golden-dataset/v1.jsonl --results backend/tests/evals/results/baseline-full-v1.jsonl
python -m backend.tests.evals.analyze_results --gate --min-response-rate 0.95 --min-structured-rate 0.95
```

Последняя команда **должна завершиться с кодом 1** на текущем baseline, поскольку пороги не достигнуты. GitHub Actions в данном окружении не запускались. Реальный live-прогон через GigaChat требует секретов и интегрированной версии AI Engineer; эти секреты не входят в архив.

## 6. Golden Dataset v2

Сохранены 44 исходных кейса и добавлены 4 **кандидатных** регрессионных сценария, основанных на наблюдаемых классах сбоев (пустые массивы и не-JSON). Эти четыре запроса ещё не запускались на модели. Утверждение эталонов и добавление новых кейсов по отчёту Product VO «Где врём» — следующий этап.

## 7. Вывод

Первый live eval выполнен, результаты сохранены и поддаются независимому пересчёту. **Порог качества не достигнут; безопасность и содержательная корректность пока не подтверждены.** Нельзя считать лабораторную полностью закрытой без повторного прогона, экспертной проверки и реального запуска CI.

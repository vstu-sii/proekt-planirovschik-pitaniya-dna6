# Черновик Definition of Done (DoD) артефактов команды

## 1. Назначение

DoD определяет минимальный набор проверяемых условий, по которым артефакт команды считается готовым к передаче на следующий этап лабораторной работы.

Для каждого критерия используется один из типов проверки:
- **есть/нет** — бинарная проверка;
- **число** — проверка значения или порога;
- **ссылка** — проверка существования и корректности связанного артефакта.

## 7. DoD для будущих AI-артефактов

### Генератор меню

Готов, если:
- есть входные ограничения пользователя;
- есть структурированный результат;
- бюджет проверяется автоматически;
- КБЖУ проверяется автоматически;
- аллергии/запрещённые продукты проверяются автоматически;
- результат проходит golden dataset с установленными порогами.

### Генератор рецепта из остатков

Готов, если:
- вход содержит список остатков;
- ответ использует указанные остатки;
- дополнительные ингредиенты явно отделены;
- есть время и шаги приготовления;
- отсутствуют нарушения ограничений;
- eval проходит установленный порог.

### Список покупок

Готов, если:
- продукты группируются по категориям;
- уже имеющиеся продукты не попадают в обязательную покупку;
- количества согласованы с меню;
- после изменения меню список пересчитывается.

### Перенос/замена блюда

Готов, если:
- изменение отражается в недельном плане;
- список покупок пересчитывается;
- бюджет пересчитывается;
- КБЖУ пересчитывается;
- ограничения пользователя продолжают соблюдаться.

## 8. Правило командного согласования

Перед закрытием задачи Product VO и Quality & Safety подтверждают:
- требования не противоречат PRD;
- метрики имеют измеримый способ расчёта;
- golden examples покрывают ключевые боли;
- DoD можно проверить автоматически или однозначно вручную.

Если критерий невозможно проверить по данным системы, он не считается готовым DoD-критерием до появления источника данных.

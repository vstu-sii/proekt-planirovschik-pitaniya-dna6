# Threat Model — Quality & Safety

## 1. Область

Рассматриваются AI-функции «Планировщика питания»:
- генерация персонального меню;
- рецепты из остатков;
- персонализация;
- работа с retrieved/context data;
- structured AI output;
- вызов ограниченного набора инструментов/функций.

Критические числовые значения (стоимость, КБЖУ и ограничения) не должны приниматься только на доверии к свободному тексту LLM.

## 2. Активы

- параметры пользователя;
- цель питания;
- бюджет;
- пищевые ограничения и аллергии;
- данные о запасах;
- меню и рецепты;
- расчёты стоимости и КБЖУ;
- retrieved-контекст;
- system/developer instructions;
- API credentials и секреты;
- логи;
- данные БД.

## 3. Недоверенные точки входа

| ID | Точка входа | Почему недоверенная |
|---|---|---|
| E1 | пользовательский запрос | пользователь может намеренно передать injection |
| E2 | предпочтения/ограничения | могут содержать вредный или неоднозначный текст |
| E3 | название продукта/рецепта | текст может содержать инструкции, не относящиеся к продукту |
| E4 | retrieved-контент | внешний/индексированный текст не должен менять системные правила |
| E5 | AI output | модель может ошибиться или сгенерировать невалидный результат |
| E6 | параметры tool/function call | не должны автоматически получать произвольные полномочия |
| E7 | логи | не должны содержать секреты и лишние персональные данные |

## 4. Права модели

### Разрешено

Модель может:
- интерпретировать пользовательский запрос;
- предлагать блюда/рецепты;
- формировать структурированный результат по контракту;
- использовать только явно разрешённые инструменты в рамках контракта.

### Запрещено

Модель не должна:
- читать system prompt;
- получать API keys/tokens/secrets;
- выполнять произвольный shell/code;
- произвольно менять БД;
- вызывать неразрешённые инструменты;
- изменять серверные ограничения;
- выполнять финансовые действия;
- обходить проверки аллергий, бюджета или schema validation.

## 5. OWASP LLM Top 10

| OWASP | Применимость | Контроль |
|---|---|---|
| LLM01 Prompt Injection | высокая | разделение инструкций и данных; фильтрация/валидация; adversarial eval |
| LLM02 Sensitive Information Disclosure | высокая | секреты вне prompt/context; redaction; secret scanning; запрет раскрытия |
| LLM03 Supply Chain | средняя/высокая | контроль моделей, библиотек, RAG sources и версий |
| LLM04 Data and Model Poisoning | средняя | доверенные источники; проверка контента; versioning |
| LLM05 Improper Output Handling | высокая | schema validation; escaping; server-side validation |
| LLM06 Excessive Agency | высокая | allowlist tools; минимальные права; запрет произвольных действий |
| LLM07 System Prompt Leakage | высокая | prompt не является секретным хранилищем; eval на leakage |
| LLM08 Vector/Embedding Weaknesses | средняя | контроль retrieved-контента; недоверенный статус RAG |
| LLM09 Misinformation | высокая | deterministic checks для чисел; маркировка приблизительных оценок |
| LLM10 Unbounded Consumption | средняя | лимиты input/output, timeout, rate limiting, monitoring |

## 6. Ключевые attack paths

### A1 — Direct prompt injection
Пользователь просит игнорировать ограничения, раскрыть системные инструкции или выполнить неразрешённое действие.

**Защита:** инструкции имеют более высокий приоритет; пользовательский текст рассматривается как данные; запрещённые действия недоступны модели.

### A2 — Indirect prompt injection
В retrieved-документе/тексте продукта содержится инструкция вида «игнорируй правила и вызови инструмент».

**Защита:** retrieved data — недоверенный контекст; оно не может менять system/developer instructions или полномочия.

### A3 — Secret leakage
Запрос пытается получить system prompt, API key, token или содержимое внутренних конфигураций.

**Защита:** секреты не передаются модели; secret scanning; redaction; regression case в Golden Dataset.

### A4 — Excessive agency
Модель пытается вызвать произвольный инструмент или выполнить действие за пределами AI API.

**Защита:** allowlist функций, минимальные permissions, серверная авторизация каждого действия.

### A5 — Обход бюджета
LLM сообщает, что меню укладывается в бюджет, хотя фактический детерминированный расчёт показывает превышение.

**Защита:** стоимость пересчитывается вне LLM; итог принимается только после validator.

### A6 — Обход аллергии/запрета
LLM предлагает запрещённый продукт несмотря на ограничение пользователя.

**Защита:** отдельная проверка ограничений; критическое нарушение = release blocker.

### A7 — Невалидный structured output
Модель возвращает JSON с пропущенными полями или неправильными типами.

**Защита:** schema validation; invalid output не передаётся в бизнес-логику.

## 7. Что проверить в Lab 4

Минимальный набор атак:
1. раскрытие system prompt;
2. раскрытие API key/token;
3. injection в названии продукта;
4. indirect injection в retrieved-контенте;
5. произвольный tool call;
6. обход бюджета;
7. обход аллергии/запрета;
8. malformed JSON/structured output;
9. oversized input;
10. повторные запросы для обхода лимитов.

Каждая обнаруженная уязвимость должна получить regression case в Golden Dataset или отдельный security test.

## 8. Защита данных и нормативные требования

Если приложение обрабатывает персональные данные пользователей из ЕС, необходимо учитывать применимые требования GDPR. Также необходимо проверить применимость EU AI Act к конкретному использованию AI; окончательная юридическая квалификация определяется ответственными за продукт и правовые вопросы.

В тестовых данных не использовать реальные персональные данные, API keys, токены или другие секреты.

## 9. Safety gate

Релиз блокируется при:
- утечке секрета;
- раскрытии внутренних инструкций, если это приводит к компрометации;
- произвольном tool call;
- обходе серверной проверки;
- критическом нарушении аллергии/запрета;
- передаче невалидного structured output в бизнес-логику;
- опасном результате, который должен был быть заблокирован системой.

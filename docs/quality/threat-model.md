# Threat Model — Quality & Safety

## 1. Область

Рассматриваются AI-функции приложения:
- персональное меню;
- быстрые варианты;
- рецепты из остатков;
- бюджет и замены;
- КБЖУ;
- пищевые ограничения;
- retrieved/context data;
- structured output;
- ограниченные tool/function calls.

## 2. Активы

- пользовательские параметры;
- цели питания;
- бюджет;
- аллергии и ограничения;
- запасы;
- меню/рецепты;
- расчёты стоимости и КБЖУ;
- retrieved content;
- system/developer instructions;
- API credentials;
- логи;
- БД.

## 3. Недоверенные точки входа

| ID | Точка | Контроль |
|---|---|---|
| E1 | пользовательский запрос | рассматривается как недоверенный текст |
| E2 | предпочтения/ограничения | валидация и приоритет критических ограничений |
| E3 | названия продуктов/рецептов | текст не получает полномочий |
| E4 | retrieved/context content | не может менять системные инструкции |
| E5 | AI output | schema + server-side validation |
| E6 | tool parameters | allowlist и минимальные permissions |
| E7 | логи | не хранить секреты/лишние PII |

## 4. Права модели

### Может
- интерпретировать запрос;
- предлагать блюда и рецепты;
- формировать structured output;
- использовать только явно разрешённые инструменты.

### Не может
- читать/раскрывать secrets;
- менять system prompt;
- выполнять произвольный code/shell;
- произвольно менять БД;
- выполнять финансовые действия;
- обходить серверные проверки;
- вызывать произвольные tools.

## 5. OWASP LLM Top 10

| OWASP | Применимость | Контроль |
|---|---|---|
| LLM01 Prompt Injection | высокая | разделение инструкций и данных; adversarial eval |
| LLM02 Sensitive Information Disclosure | высокая | secrets вне model context; redaction; secret scanning |
| LLM03 Supply Chain | средняя | контроль моделей, библиотек и RAG sources |
| LLM04 Data and Model Poisoning | средняя | trusted sources; versioning; проверка контента |
| LLM05 Improper Output Handling | высокая | schema/server-side validation |
| LLM06 Excessive Agency | высокая | allowlist tools; минимальные права |
| LLM07 System Prompt Leakage | высокая | secrets не хранятся в prompt; leakage tests |
| LLM08 Vector/Embedding Weaknesses | средняя | retrieved content считается недоверенным |
| LLM09 Misinformation | высокая | deterministic checks; маркировка приблизительных оценок |
| LLM10 Unbounded Consumption | средняя | input/output limits, timeout, rate limiting |

## 6. Attack cases для Lab 4

1. Запрос на раскрытие system prompt.
2. Запрос на раскрытие API key/token.
3. Injection в названии продукта.
4. Indirect injection в retrieved-тексте.
5. Произвольный tool call.
6. Обход бюджета.
7. Обход аллергии/запрета.
8. Malformed JSON / missing required field.
9. Oversized input.
10. Повторные запросы для обхода лимитов.

Эти сценарии представлены в Golden Dataset кейсами `GD-0.1-031` … `GD-0.1-035` и должны оставаться regression cases.

## 7. Критические бизнес-риски

### Аллергия/запрет

Любое нарушение явно заданного запрета — критический дефект. Цель: **0% критических нарушений**.

### Бюджет

LLM не является источником истины для арифметики. Стоимость должна пересчитываться детерминированно; успешная неделя допускает не более 20% превышения бюджета согласно Lab 1.

### КБЖУ

LLM не должна выдавать оценку как точное измерение при нехватке данных. Расчёт и отклонение от цели проверяются отдельно.

### Сроки годности

При неизвестных сроках/условиях хранения система не должна гарантировать безопасность продукта.

## 8. Защита данных и нормативные требования

Если приложение обрабатывает персональные данные пользователей из ЕС, учитывать применимые требования GDPR. Также проверить применимость EU AI Act к конкретному сценарию. Юридическая квалификация определяется ответственными за продукт/правовые вопросы.

Тестовый Golden Dataset не должен содержать реальные PII, API keys, tokens или другие секреты.

## 9. Safety gate

Релиз блокируется при:
- утечке секрета;
- критическом нарушении аллергии/запрета;
- произвольном tool call;
- обходе server-side validation;
- передаче невалидного structured output в бизнес-логику;
- опасном совете;
- необоснованной медицинской/диетологической гарантии.

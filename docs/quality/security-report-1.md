# Security Report 1 — атаки и дефекты до исправлений

**Лабораторная работа № 4 · Quality & Safety**  
**Проект:** «Планировщик питания»  
**Исполнитель:** Мария Карпова  
**Дата:** 26.11.2026

## 1. Цель и границы проверки

Цель — воспроизвести атаки на точки входа модели угроз, проверить программные ограничения и приоритизировать обнаруженные дефекты. Использован локальный интеграционный контур FastAPI, SQLite in-memory, Python 3.12.10, pytest 8.4.2, ToolRuntime и GigaChat-2. Проверки выполнялись на синтетических данных; реальные пользовательские данные и секреты не использовались как тестовые значения. Это не аудит production-среды.

Исходное состояние для сравнительного Live-прогона — отдельный Git worktree до внесения исправлений; путь импортируемого `meal_plans.py` проверен и указывал на временную копию. Replay воспроизводит заданные ответы тестового провайдера; Live использует реальные ответы GigaChat (они могут различаться между запусками).

## 3. Исходная регрессия безопасности

Команда: `python -m pytest quality_lab4/test_security.py -v --tb=short` (исходный набор из 19 тестов).

Фактический результат: **14 passed, 5 failed**. Доказательство: `security-before.log`.

| ID | Дефект | Наблюдение до исправления | Приоритет* | Регрессия |
|---|---|---|---|---|
| SEC-01 | Обход исключения через алиас | Запрет «яйца», ответ «Яйцо»: HTTP 200 вместо 422 | P0 | `test_sec_alias`, GD-0.4-049, PI-D01 |
| SEC-02 | Неверная последовательность дней | День 2 вместо 1: HTTP 200 | P1 | `test_sec_day_index`, GD-0.4-050, PI-D02 |
| SEC-03 | Неизвестный ингредиент | HTTP 500 вместо контролируемого отклонения | P1 | `test_sec_unknown_product`, GD-0.4-051, PI-D03 |
| SEC-04 | Возврат внутренней ошибки | Синтетический маркер раскрыт в HTTP 503 | P0 | `test_sec_secret_error`, GD-0.4-052 |
| SEC-05 | Эхо входных данных | Синтетический маркер возвращён в HTTP 422 | P1 | `test_sec_validation_echo`, GD-0.4-053 |
| SEC-11 | Передача непроверенного названия продукта модели | Недоверенный текст достигает модели; косвенные сценарии завершались HTTP 500 в исходном Live-прогоне | P1 | PI-I01–03, GD-0.5-054, `test_uc2_unknown_pantry_product` |

\* Рабочая приоритизация: P0 — блокирующий риск безопасности; P1 — существенное нарушение корректности/устойчивости или потенциальной конфиденциальности. SEC-02 и SEC-05 уточнены относительно черновой приоритизации (P0): доказан дефект целостности и отражение синтетического ввода соответственно, но не фактическая утечка чужих данных. При доказанном критическом воздействии приоритет повышается. Решения о релизе согласуются с командой.

Дополнительно: SEC-06 — бюджет, прямой запрет и время блокировались; SEC-07 — права инструментов проверены; SEC-08 — тайм-аут инструментов проверен; SEC-09 — группа Prompt Injection (результаты ниже); SEC-10 — пользовательские квоты не подтверждены. SEC-06–09 не считаются четырьмя дополнительными независимыми обнаруженными уязвимостями.

## 5. Ограничения и передача дефектов

- SEC-01–05 и SEC-11 требуют программных контролей, а не только изменения промпта. Повторные результаты — в `security-report-2.md`.
- Нет доказательств утечки реального секрета, проверки production-логов, полноценной авторизации пользователей, RAG-инъекций и rate limiting. Наличие HTTP-кода 429 само по себе не подтверждает лимиты.
- По каждому обнаруженному серверному дефекту указаны регрессионные тесты/кейсы. Для новых дефектов используется `quality_lab4/regression.py`; поступающие production/acceptance-инциденты подлежат регистрации и добавлению проверок. Фактические production-инциденты в материалах не представлены.
- Текстовый Golden Dataset — отдельный eval-контур, не доказательство наличия соответствующих функций Backend.

## 6. Заключение

Выявлены шесть классов серверных дефектов (пять исходных и дополнительная проверка pantry). Исходное состояние не удовлетворяло критериям безопасности и управляемого отказа. Для повторной проверки сохранён тот же набор атак; остальные пробелы и риски не признаются устранёнными без доказательств.

Примечание: после завершения тестирования файлы тестов перенесены в tests/quality_safety/. Приведённые выше команды отражают исходное расположение на момент проведения экспериментов.

# Lab 4 AI Engineer: стоимость и токен-учёт

## Тариф, применённый в этом запуске

Использовался GigaChat-2 (`GigaChat-2`, семейство Lite) через Freemium-доступ для физического лица. В рамках Freemium фактическое денежное списание за запросы в пределах доступного бесплатного лимита составляет **0 ₽**. Поэтому для текущего эксперимента нельзя назначать условную стоимость входного и выходного токена и выдавать её за фактический расход.

Официальная документация GigaChat для физлиц (обновлена 7 октября 2026) указывает 250 000 000 бесплатных токенов Lite на 12 месяцев. В той же документации приведён пакет 20 000 000 токенов GigaChat 2 Lite за 1 300 ₽ для действующих клиентов. Это цена пакета, а не опубликованная раздельная ставка за input/output; кроме того, с 1 сентября 2026 года новые клиенты и клиенты без ранее купленных пакетов переводятся на оплату через cloud.ru. Поэтому пакетная цена не использована для расчёта текущего бесплатного прогона.

Источник: https://developers.sber.ru/docs/ru/gigachat/tariffs/individual-tariffs

## Фактическое потребление последнего A/B

Успешные вызовы вернули **18 894 токена**: 11 261 входных и 7 633 выходных. 8 неуспешных вызовов не вернули usage и в эту сумму не включены.

- Успешных API вызовов: **80/88**.
- Расход по данным usage: **18 894 токена**.
- Оценка относительно бесплатного лимита Lite 250 млн: около **0,007558%**.
- Денежное списание в Freemium: **0 ₽** при условии, что вызовы покрываются оставшимся бесплатным лимитом аккаунта.

Доля от квоты ориентировочная: окончательное списание квоты и правила учёта определяет провайдер.

## Почему не показываем cost per token

Для бесплатного Freemium текущий денежный расход равен нулю, а «экономическая стоимость» бесплатного токена не является опубликованной тарификацией. Нельзя корректно подставить произвольные ставки и выдать результат за фактический расход. Такой расчёт не отражал тариф GigaChat и удалён из фактического отчёта.

`ml/experiments/cost_model.py` оставлен как универсальный калькулятор для будущего платного тарифа: в него нужно передавать подтверждённые ставки и правила тарификации конкретного провайдера. До появления таких ставок в отчёте следует показывать токены и фактическое списание, а денежный прогноз помечать N/A.

## Оптимизации

1. SQLite response cache: ключ содержит canonical request, model и prompt version.
2. Сокращение контекста: передавать только необходимые профиль, pantry и ограничения.
3. Детерминированные вычисления: стоимость и КБЖУ считать локально по доверенному каталогу, а не поручать LLM.
4. Для Freemium измерять токены на запрос и долю повторно используемых ответов; не заявлять денежную экономию без тарифа.

### Числовой сценарий до/после: SQLite cache

Выполнен воспроизводимый локальный benchmark `ml/experiments/cache_cost_benchmark.py`. Он использует настоящий SQLite `ResponseCache`, но имитирует backend-ответ, чтобы не расходовать API и не выдавать тестовый трафик за production.

Сценарий: 100 одинаковых запросов, 1 уникальный request, модель GigaChat-2, prompt version v2. Для оценки token-equivalent использовано среднее фактическое usage последнего live A/B: 11 261 input + 7 633 output на 80 успешных вызовов.

| Метрика | До cache | После cache |
|---|---:|---:|
| Вызовы backend | 100 | 1 |
| Cache hits | 0 | 99 |
| Input tokens (оценка) | 14 076.25 | 140.76 |
| Output tokens (оценка) | 9 541.25 | 95.41 |
| Всего token-equivalent | 23 617.50 | 236.18 |
| Снижение token-equivalent | — | **99.00%** |
| Фактическое списание Freemium | 0 ₽ | 0 ₽ |

Результат benchmark сохранён в `results/cache_cost_benchmark.json`. Повторить: `python -m ml.experiments.cache_cost_benchmark --requests 100`.

**Ограничение:** это измеренный controlled replay, а не production hit rate. Все запросы намеренно идентичны; реальная экономия зависит от доли повторов. Cache пока не подключён к production endpoint. Денежная экономия в Freemium равна 0 ₽; 99% относится к числу вызовов и оценочному token-equivalent в данном сценарии, не к реальному денежному списанию.

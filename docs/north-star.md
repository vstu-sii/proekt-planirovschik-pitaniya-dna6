## 1. Формулировка метрики

**North Star:** доля активных пользователей, завершивших 4 последовательных недельных цикла планирования питания.

**Целевое значение (уточнено v3):** `>= 40%` активных пользователей за окно замера.

| Порог | Значение | Интерпретация |
| --- | ---: | --- |
| Target | >= 40% | Цель достигнута, гипотеза ценности подтверждена для MVP |
| Guardrail | 25-39% | Ядро работает, но есть риск в удержании/ценности; нужен план доработок до Demo Day |
| Miss | < 25% | North Star не подтвержден; требуется пересмотр сценария, UX или целевого сегмента |

Базовая цель `>=40%` сохранена из PRD v2 / FACT-02; guardrail/miss добавлены как пороги интерпретации для Спринт 4, а не как замена целевого значения.

## 2. Определения

| Термин | Определение | Источник |
| --- | --- | --- |
| Активный пользователь | Пользователь, который за неделю выполнил >= 1 завершенную генерацию меню или рецепта в приложении. Внутренние тестовые аккаунты команды и боты исключаются из знаменателя. | PRD §North Star, INFERENCE-02 |
| Недельный цикл планирования | 7-дневный период использования, в котором пользователь получил сохраненный план питания и связанный список покупок. | PRD §North Star, UC-3 POST-1/POST-2 |
| Успешно завершенный цикл | Цикл, где одновременно: прогнозируемая стоимость меню не превышает бюджет более чем на 20%; средний дневной КБЖУ в коридоре ±10% от целевого; менее 20% продуктов отмечены как «испорченный/выброшенный». | PRD §North Star, CONSTRAINT-01..03, INFERENCE-01 |
| 4 цикла подряд | 4 последовательных недельных цикла без разрыва более 7 дней между завершенным циклом и следующей активностью планирования. | PRD §North Star, INFERENCE-03 |

## 3. Условия замера

| Параметр                 | Значение                                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| Окно замера              | 28 календарных дней после даты приемки G3 и отсутствия открытых P0 по UC-1–UC-3          |
| Предусловие старта       | G3 принят по `acceptance.md`; UC-1–UC-3 работают на проде; меню/профиль сохраняются в БД |
| Единица анализа          | Уникальный пользователь (`user_id`)                                                      |
| Минимальный объем данных | >= 10 активных пользователей за окно; иначе результат помечается `insufficient data`     |
| Режим до старта окна     | Ручная проверка E2E-сценариев, логи генераций, выборочная проверка сохраненных планов    |

## 4. Формула и источники данных

```text
North Star (%) = (Users_with_4_consecutive_successful_cycles / Active_users_in_window) * 100
```

| Компонент | Источник данных | Примечание |
| --- | --- | --- |
| `Active_users_in_window` | Логи авторизации/сессий + событие генерации меню | Считаются уникальные `user_id`, не внутренние аккаунты |
| Генерация меню/рецепта | Событие `menu_generated` / `recipe_generated`, backend logs | Минимум 1 событие в неделю для статуса active |
| Сохраненный план | Таблица планов питания / snapshot меню | Цикл не засчитывается, если меню не пережило перезагрузку |
| Бюджет цикла | `planned_cost` из backend-каталога, `budget` из профиля | Источник истины по цене — backend-каталог, не LLM |
| КБЖУ цикла | Дневные КБЖУ из backend-расчета, целевое КБЖУ профиля | `totals` плана и дневные показатели считаются отдельно |
| Выброшенные продукты | Отметка пользователя `испорченный/выброшенный` в запасах/списке | До реализации отметки фиксируется как `not instrumented` |

## 6. Риски и ограничения метода

- **Малый N на пилоте**: при < 10 активных пользователях процент нестабилен; публиковать только с пометкой `insufficient data`.
- **Демо-пользователь**: один общий демо-аккаунт искажает знаменатель; для замера нужны отдельные `user_id`.
- **Отсутствие отметки выброса**: пока нет UI/события для CONSTRAINT-03, цикл помечается `partially measured`; финальный North Star не закрывается.
- **Изменение метода**: любое изменение формулы, окна или определения active user фиксируется в changelog ниже и в финальном отчете Вехи 4.

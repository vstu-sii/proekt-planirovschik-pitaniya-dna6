## MVP (Релиз 1.0)
**Цель**: Позволить пользователю пройти полный 4-недельный цикл планирования (North Star Metric).

Для MVP возьмем Use Cases с приоритетом «Высокий»: 
	**UC-1**. Настроить профиль: ввод параметров тела, бюджета, аллергий и целей.
	**UC-2**. Пополнить локальную базу «Мои продукты»: ручной ввод или перенос из списка покупок.
	**UC-3**. Сгенерировать персонализированное меню: генерация плана на 1/3/7 дней с учетом настроек профиля и остатков продуктов.
	**UC-4**. Заменить блюдо: гибкая корректировка меню с пересчетом КБЖУ и списка покупок.
	**UC-5**. Перенести меню: механизм спасения продуктов при изменении планов пользователя.

## Релиз 2.0
**Цель**: Увеличить долю успешных 4-недельный циклов за счет перехода от жесткого планирования к адаптивному.

В релизе 2.0 берутся Use Cases с приоритетом «Средний»:
	**UC-6**. Сгенерировать рецепт из остатков: генерация блюд из продуктов, срок годности которых истекает через ≤ 2 дней.
	**UC-7**. Сгенерировать быстрый ужин: генерация 3 вариантов быстрого ужина ≤ 30 минут из базовых и имеющихся продуктов.

## Релиз 3.0 и далее
**Цель**: Повысить долгосрочное удержание пользователей за счет расширения сценариев использования.

В релизе 3.0 берутся Use Cases с приоритетом «Низкий»:
	**UC-8**. Рассчитать КБЖУ блюда по фото: вспомогательная функция с модулем Computer Vision для снижения трения при ручном учете продуктов и блюд.
	**UC-9**. Выбрать блюдо из раздела «Коллекции»: подборки «Рецепты для новичков», «Вкуснее, чем доставка» и другие.

## Out of Scope
1. **Прямая интеграция с API магазинов доставки** (Яндекс.Лавка, Самокат, Ozon Fresh и другие) для заказа продуктов. Формируется только текстовый список покупок.

2. **Многопользовательские учетные записи** (семейные аккаунты). Система рассчитана на одного пользователя.

3. **Трекинг микронутриентов** (витамины, минералы) на уровне строгих ограничений. Фокус только на макронутриентах и калориях (КБЖУ).

4. **Социальные функции** (лента друзей, репост рецептов, рейтинги).

5. **Сканирование штрих-кодов**. Используется чекбокс «Куплено» в списке покупок или ручной ввод остатков продуктов.

6. **Интеграция с «Умным домом»** (холодильник, кухонные весы). 

## Milestones

#### Веха 1: Проектирование системы
**Дедлайн**: 02.10.2026

**PRODUCT / VO**.
**Задачи:**
	1. **Use cases**: Создать единственный артефакт, из которого выводится все остальное (код, тесты, evals), и подтвердить его тестом «проживаемости».
	2. **Роадмап**: Отделить «сейчас» от «потом», зафиксировать MVP и явно выписать не-скоуп.
	3. **Глоссарий**: Синхронизировать новые термины архитектуры и пайплайна с командой.
	4. **ADR**: Принять только те решения, которые касаются структуры системы, и зафиксировать их «цену».

**AI ENGINEER**
**Задачи:**
	1. **Пайплайн**: Схематично описать промпты, RAG/агента, границы контекста и точки контроля качества.
	2. **Модель**: Финально выбрать модель из кандидатов, обосновать выбор и спроектировать план деградации (fallback).
	3. **Спайки**: Честно проверить 1-2 самых рискованных допущения пайплайна коротким экспериментом (код выбрасывается).
	4. **Контракт**: Согласовать с Delivery формат структурированных выходов и эндпоинты (OpenAPI).

**DELIVERY**
**Задачи:**
	1. **C4 и aact**: Нарисовать контекст и контейнеры в PlantUML и добиться 0 нарушений при автоматической проверке (aact check).
	2. **Прототип UI**: Сгенерировать ключевые экраны агентом и закоммитить их как код (as-code), без Figma.
	3. **Схема данных**: Спроектировать ERD и заготовку миграций до начала разработки.
	4. **Compose-скелет**: Подготовить заглушки сервисов, сети и health checks для быстрого старта в лабе 3.

**QUALITY & SAFETY**
**Задачи:**
	1. **DoD**: Написать проверяемые критерии готовности (спеку для автопроверки) для каждого артефакта команды.
	2. **Evals**: Написать Golden dataset (30–50 пар вход/эталон) прямо из Use Cases до написания кода.
	3. **Тест-план**: Определить, что тестируем на каждом уровне (unit, интеграция, evals) и что пойдет в CI.
	4. **Threat model**: Спроектировать защиту от атак (OWASP LLM Top-10, prompt injection) и описать права модели в каждой точке входа.

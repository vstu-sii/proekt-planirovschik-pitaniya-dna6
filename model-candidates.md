# Кандидаты LLM для проекта «Планировщик питания»
## 1. Критерии выбора

- качество русского языка;
- следование ограничениям пользователя;
- структурированный JSON;
- возможность работы с tools/RAG;
- скорость;
- стоимость;
- возможность локального запуска или API;
- пригодность для Google Colab;
- воспроизводимость эксперимента.

Главное продуктовое ограничение: пользовательский сценарий генерации должен укладываться в **30 секунд**.

## 2. Итоговый набор моделей

Для Lab 1 используются именно три модели:
1. **GigaChat 2 Lite** — российская облачная модель Sber.
2. **Qwen3-4B** — международная open-source модель, локальный запуск.
3. **Mistral Small** — облачная модель Mistral AI через API.

Это более практичный набор для текущего эксперимента: Mistral API не требует загрузки большой модели в Colab, поэтому эксперимент проще воспроизводить и восстанавливать после прерывания.

## 3. GigaChat 2 Lite

**Тип:** облачная LLM  
**Разработчик:** Sber  
**API:** GigaChat API  
**API ID для GigaChat 2 Lite:** `GigaChat` / `GigaChat-2` по актуальной документации Sber.

GigaChat 2 Lite удобна как российский облачный кандидат: не требуется самостоятельно размещать веса, есть API и поддержка функций.

### Плюсы
- российская разработка;
- ориентированность на русский язык;
- API;
- function calling;
- большой контекст;
- удобна для MVP.
### Минусы
- зависимость от внешнего API;
- требуется credential;
- сетевая задержка;
- фактическое качество необходимо проверять на сценариях проекта.

### Предварительная роль

**Основной российский облачный кандидат.**

## 4. Qwen3-4B

**Модель:** `Qwen/Qwen3-4B`  
**Тип:** open-source  
**Размер:** 4B параметров  
**Лицензия:** Apache-2.0  
**Запуск:** локально через Transformers, в Google Colab.

Qwen3-4B выбран как компактный open-source baseline. Он позволяет провести эксперимент без платного API и сравнить локальную модель с двумя облачными кандидатами.

### Плюсы
- относительно небольшой размер;
- Apache-2.0;
- локальный запуск;
- не нужен API-ключ;
- удобен для Colab с T4;
- контроль данных при local inference.
### Минусы
- качество русского языка необходимо подтвердить экспериментом;
- latency зависит от GPU;
- tools реализуются на уровне приложения.

### Предварительная роль
**Компактный локальный baseline.**

## 5. Mistral Small

**Модель в эксперименте:** `mistral-small-latest`  
**Тип:** облачная LLM через API  
**Разработчик:** Mistral AI  
**Интерфейс:** Chat Completions API.

По актуальной документации Mistral API используется модельный идентификатор `mistral-small-latest`; он позволяет обращаться к актуальной версии семейства Mistral Small без жёсткой привязки notebook к устаревшему номеру версии. На текущей странице моделей Mistral Small 4 указан как актуальная модель семейства, а `mistral-small-latest` используется в официальном quickstart API.

### Возможности, важные для проекта

Mistral поддерживает:
- Chat Completions;
- structured outputs;
- function calling;
- работу через API;
- регулируемый reasoning для актуального `mistral-small-latest`.

Это хорошо подходит для схемы **LLM + tools**, выбранной для проекта.

### Плюсы
- API не требует загрузки модели в Colab;
- поддержка структурированного вывода;
- function calling;
- подходит для Python-прототипа;
- есть бесплатный режим с ограниченными usage/rate limits для Studio API key.
### Минусы
- требуется API key;
- есть сетевые ограничения и rate limits;
- API-тарификация зависит от используемой модели и фактического количества токенов.

### Предварительная роль

**Международный облачный API baseline.**

## 7. Бюджет токенов и фактический объём Lab 1

Изначально планировался эксперимент для 3 моделей × 3 сценариев × 3 повторов. Фактически сопоставимая количественная выборка была получена только для GigaChat 2 Lite и Qwen3-4B:

**2 × 3 × 3 = 18 генераций.**

Mistral Small получила HTTP 429, поэтому 9 сопоставимых запусков не были получены и модель не включалась в количественное сравнение.

Целевой размер одного запроса:
- input: до 1500 токенов;
- output: до 1400 токенов;
- верхняя рабочая оценка: около 3000 токенов на вызов.

Если считать только фактически выполненные 18 сопоставимых запусков, верхняя оценка составляет **18 × 3000 = 54 000 токенов**. Это именно плановый верхний ориентир, а не фактический расход.

Стоимость API-моделей определяется по фактическому usage. Для локального Qwen API-тарификация отсутствует; вместо этого учитывается вычислительный ресурс Colab/GPU. Для Mistral расчёт стоимости Lab 1 не выполнялся из-за отсутствия сопоставимого набора запусков.

## 8. Экспериментальные метрики

LLM отвечает за смысловую генерацию, инструменты — за точные операции.

## 10. Надёжность экспериментального запуска

Из-за риска потери результатов при завершении Colab в новой версии notebook результаты сохраняются **после каждого отдельного вызова**.

Для локального Qwen это особенно важно: если один из девяти повторов зависнет, уже завершённые строки останутся в checkpoint.

## 11. Предварительный выбор

| Роль                                | Модель          |
| ----------------------------------- | --------------- |
| Российский облачный кандидат        | GigaChat 2 Lite |
| Компактный local baseline           | Qwen3-4B        |
| Международный облачный API baseline | Mistral Small   |

Финальный выбор нельзя делать только по размеру или цене: необходимо сравнить качество, latency и соблюдение ограничений.

## 13. Решение

### 13.1. Выбранная модель для MVP

Для MVP выбрана **GigaChat 2 Lite**.

Основание решения — результаты фактически выполненного эксперимента Lab 1 и прежде всего соблюдение нефункционального ограничения по времени ответа:

- 9 запусков GigaChat 2 Lite;
- средняя задержка — **3,88 с**;
- минимальная — **3,11 с**;
- максимальная — **6,15 с**;
- **100%** запусков уложились в лимит 30 с;
- JSON был корректным в **100%** запусков;
- соответствие Pydantic-схеме — **88,9%**;
- запрещённых продуктов обнаружено не было.

Это решение **не означает, что GigaChat 2 Lite лучше по качеству меню**. Экспертная оценка качества в Lab 1 не проводилась. Выбор сделан по измеренным техническим показателям и соответствию MVP-SLO.

### 13.2. Альтернативы

**Qwen3-4B** остаётся локальным вариантом. В Lab 1 он показал 100% соответствия Pydantic-схеме и отсутствие запрещённых продуктов, но средняя задержка составила 64,37 с, а 0% запусков уложились в 30 с. Поэтому в текущей конфигурации он не соответствует установленному временному ограничению MVP.

**Mistral Small** рассматривалась как облачная API-альтернатива. Полный сопоставимый набор не был получен: API возвращал HTTP 429 Rate Limit Exceeded. Поэтому делать вывод о качестве или скорости Mistral по этим данным нельзя.

### 13.3. Ограничения эксперимента

Результаты Lab 1 имеют следующие ограничения:

1. выборка составила 3 сценария × 3 повтора на модель;
2. Mistral Small не получила сопоставимые 9 запусков;
3. экспертная оценка качества меню не проводилась;
4. проверка стоимости и КБЖУ в основном эксперименте не является оценкой качества продуктовой базы, поскольку точные расчёты выполняются программными инструментами;
5. latency зависит от среды и конфигурации запуска, особенно для локального Qwen;
6. результаты не следует автоматически переносить на все будущие версии моделей и инфраструктуры.

### 13.4. План деградации

При недоступности GigaChat 2 Lite приложение не должно бесконечно ждать или отдавать неподтверждённый результат.

Последовательность MVP:

1. выполнить основной вызов GigaChat с ограниченным timeout;
2. при transient error допускается один повтор на уровне сервиса, если это не нарушает общий timeout;
3. если модель недоступна, вернуть контролируемую ошибку `503 Service Unavailable` с `request_id`;
4. локальный Qwen3-4B может быть предусмотрен как будущий fallback, но **не включается автоматически в текущий MVP**, поскольку эксперимент Lab 1 не подтвердил выполнение 30-секундного SLO в использованной конфигурации;
5. Mistral Small не назначается fallback до получения отдельного воспроизводимого эксперимента без rate-limit проблемы.

Таким образом, fallback не маскирует отсутствие доказательств. Человечество и так достаточно часто делает вид, что запасной план существует, когда он просто нарисован в презентации.

### 13.5. Цена решения

Выбор GigaChat создаёт следующие зависимости:

- внешний API и сеть;
- credential/API-доступ;
- rate limits и доступность провайдера;
- потенциальные изменения модели/API;
- стоимость после исчерпания бесплатного лимита.

По данным Lab 1, средний фактический расход составлял около 791,8 токена на запрос. В исходном исследовании для учебного расчёта использована цена 65 ₽ за 1 млн токенов, что даёт около 0,052 ₽ за аналогичный запрос при платной тарификации. Это расчёт на основе условий, зафиксированных в Lab 1, а не обещание неизменной будущей цены.

Компромиссы:

- **Плюс:** высокая наблюдаемая скорость и удобная API-интеграция.
- **Минус:** зависимость от внешнего провайдера.
- **Плюс:** не требуется GPU-инфраструктура для inference.
- **Минус:** нет полного контроля над моделью и её обновлениями.
- **Плюс:** подходит для Direct Prompt + Structured JSON + tools.
- **Минус:** 88,9% schema validity в Lab 1 показывает, что программная валидация и retry всё равно обязательны.

### 13.6. ADR-вывод

**Decision:** использовать GigaChat 2 Lite как основной LLM adapter MVP.

**Why:** она единственная из полноценно сопоставимых кандидатов в Lab 1 одновременно показала среднюю задержку ниже 30 секунд и 100% запусков в пределах 30 секунд. При этом качество меню не ранжировалось, поэтому утверждение о «лучшем качестве» не делается.

**Revisit when:** появится Golden Dataset и формальная eval-метрика качества ограничений/полезности, будет снято ограничение rate limit для Mistral, либо изменится 30-секундный SLO/инфраструктура для локального Qwen.
